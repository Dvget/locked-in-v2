## Repository layout

The repo root is both the Obsidian vault (the "project brain": Markdown docs) and the Git repository. The React Native / Expo SDK 57 app lives in `app/`. Everything below is run from `app/` unless noted.

## Commands

- Web preview: `npx expo start --web` (or `npm run web`). Metro for a Dev Client: `npx expo start --dev-client --clear`.
- Type check: `npx tsc --noEmit`. Bundle sanity check: `npx expo export --platform web --output-dir <temp dir>` (do not export into the repo).
- No linter or formatter is installed. A test runner (`vitest`) is added in rebuild slice 1; check `package.json` before assuming `npm test` exists.
- Add dependencies with `npx expo install <pkg>` (picks SDK-compatible versions). Read the versioned Expo docs first (`app/AGENTS.md`).
- Windows PowerShell blocks `npm.ps1`/`npx.ps1` (execution policy, intentionally unchanged): use `npm.cmd`/`npx.cmd` there. Git Bash runs `npx` directly.
- Native iOS builds only run in GitHub Actions: `.github/workflows/build-ios-dev-client.yml` (manual `workflow_dispatch`, macOS, Expo prebuild, unsigned IPA artifact; no EAS, no Apple credentials). `app/ios` is generated by prebuild and git-ignored. The free plan's Actions minutes are limited and were exhausted in September 2026 (see `STATUS.md`): check usage and get the user's OK before dispatching a run, except inside the autonomous rebuild, where `60_Workflow/AUTONOMOUS_REBUILD.md` allows a limited number of builds while the repo is public.

## App architecture

`App.tsx` -> `SafeAreaProvider` -> `AppFrame` (web only: limits width to 430 px, native renders unchanged) -> `RootNavigator`.

- Navigation (React Navigation 7, dynamic API, provisional per D-048): `RootNavigator` is a native stack (`Tabs`, `Workout`, `Running`, `WeeklyReport`); `TabNavigator` holds the bottom tabs Dashboard / Progress / Settings. Screen param lists live in `src/types/navigation.ts`. Workout, Running and Weekly Report are opened from the Dashboard, not from tabs.
- Dashboard V1 is assembled from small components in `src/components/dashboard/` fed by static dummy data in `src/data/dashboardDummy.ts`. There is no real data layer yet: no database, state management, charts library or icon library. The mini charts are plain Views (`Sparkline`).
- Styling tokens are in `src/theme` (colors incl. orange brand accent and violet running accent, spacing, radius, typography). Dark mode only (`userInterfaceStyle: "dark"`).
- Workout, Running, Progress, Settings and Weekly Report screens are still placeholders.

## Working conventions specific to this repo

- Never commit images or screenshots. `20_Design/References/` is git-ignored; describe important images as text in the docs.
- Commits use the repo-local anonymous GitHub email (`<id>+Dvget@users.noreply.github.com`); do not switch to the user's private email.
- Ask before anything hard to undo: force-push or history rewrite, changing repo visibility, deleting runs. Dispatching build runs needs the user's OK too, except inside the autonomous rebuild (see its work order).
- Explain in plain German, short, and say in one sentence what any technical term means.
- Create files with the Write tool rather than shell heredocs; quotes/apostrophes in heredocs broke a command earlier.
- After substantial work, update `STATUS.md` (and `DECISIONS.md` only for real decisions). Keep the "Next steps" section of `STATUS.md` current: it is the handoff to the next chat.
- Chat handoff: when a chat gets long (around 60-70 % of the context window) or a work block ends, update `STATUS.md`, tell the user a fresh chat is a good idea, and remind them that the new chat starts by reading the project files.
