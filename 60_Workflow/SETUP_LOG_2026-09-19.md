Scheme detection went through two iterations before the commit:
1. First version derived the scheme from the workspace name and verified it against `xcodebuild -list -json`.
2. Final version does not derive the scheme from the workspace name. It reads the workspace schemes with `xcodebuild -list -json`, removes the schemes defined in `Pods/Pods.xcodeproj` (the workspace list also contains all CocoaPods schemes) and takes the first remaining scheme. It logs the workspace and the selected scheme and aborts only if no scheme remains.

Commit: `ci: add unsigned iOS dev client build`

### SideStore-Installationsfehler und Korrektur (2026-09-19)

SideStore lud die IPA von Build 2, brach aber ab: "The downloaded version does not match the build number specified by the source. Expected 2, found 1". Ursache: `source.json` nannte Build 2 (GitHub-Lauf-Nummer), in der App stand aber der Expo-Standard `CFBundleVersion = 1`. Korrektur im Workflow: Die Lauf-Nummer wird vor dem Prebuild als `ios.buildNumber` in `app.json` gesetzt (nur auf dem Runner, nicht committet), und nach dem Bauen prüft ein Schritt Version, Build-Nummer und Bundle-ID der gebauten App. Lauf `35458949652`: success, Build 3, Prüfung `id=app.lockedin.v2 version=1.0.0 build=3` passt.

Nebenbefund: Die alte SideStore-Quelle "LOCKED IN" (Legacy-Verteil-Repo) liefert 404 und erzeugt in SideStore "Decoding failed"; die installierte alte App ist davon nicht betroffen.
